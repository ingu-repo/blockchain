## README-ready explanation for this blockchain demo

### Project overview
This project is a small blockchain implementation written in Python to demonstrate the core concepts behind blockchains: hashing, proof of work, block chaining, and transaction signing.

It is intended as an educational example rather than a production blockchain system.

---

### Core components

#### 1. Block
A block represents one unit in the blockchain. Each block contains:
- a timestamp
- its index in the chain
- the hash of the previous block
- the transaction list
- a nonce value
- its own hash

The block hash is generated by serializing the block data into JSON and hashing it using SHA-256.

```python
serialized = json.dumps({...}, sort_keys=True).encode()
return hashlib.sha256(serialized).hexdigest()
```

This makes each block tamper-evident. If any field changes, the hash changes as well.

---

#### 2. Blockchain
The `BlockChain` class manages the chain and validates block integrity.

It stores:
- the difficulty level for mining
- the chain list
- the genesis block

The chain validation checks:
- the previous block hash matches the current block’s `prev_hash`
- the current block hash matches its recomputed hash

This ensures that the blockchain is not easily modified after creation.

---

#### 3. Proof of work
Mining is implemented by adjusting the nonce until the hash begins with a specific number of zero characters.

```python
hash_pattern = "0" * self.difficulty
```

This makes the block creation process intentionally expensive and demonstrates the concept of proof of work.

The higher the difficulty, the more computation is required to mine a valid block.

---

#### 4. Wallet and transaction signing
The `Wallet` class creates an ECDSA keypair:
- a private key
- a public key

A transaction is signed with the sender’s private key, and the signature is stored in the transaction as a hex string for JSON safety.

```python
tx["signature"] = self.private_key.sign(payload).hex()
```

Because raw binary signatures cannot be serialized directly into JSON, converting them to a hex string makes the transaction safe to store and hash.

---

#### 5. Signature verification
When verifying a transaction, the code reconstructs the payload that was signed, then checks the signature using the public key.

```python
public_key.verify(bytes.fromhex(tx["signature"]), payload)
```

If the transaction data was modified after signing, verification fails, which is exactly what protects the transaction from tampering.

---

### Example flow
1. A wallet creates a transaction.
2. The wallet signs the transaction payload.
3. The transaction is added to a list of transactions.
4. A block is created from the transactions.
5. Mining finds a valid nonce.
6. The block is appended to the blockchain.
7. The blockchain verifies the previous hash and transaction signatures.

---

### Why this project matters
This project demonstrates the basic building blocks of blockchain systems:
- blocks
- hashing
- chaining
- digital signatures
- proof of work

It is a simple educational model and helps explain how modern blockchain systems keep data secure and resistant to tampering.

---

### Limitations
This implementation is intentionally simplified. It does not include:
- a real peer-to-peer network
- a full UTXO model
- wallet balances from spent/unspent outputs
- transaction mempool
- full blockchain consensus
- persistent storage
- production-grade security and validation

It is best viewed as a learning prototype for blockchain concepts.

python unicoin.py
